Anchor print and ticket print, subject matter and format

- DECIDED (Patrick) - Anchor print subject moves from a single food/drink object to scenes (a restaurant, a bar, a kitchen) in rotation with single-object prints, month to month. Reason: a scene in one color holds up better at small size than an object does, and alternating keeps a 12-month grid from feeling monotonous.
- DECIDED - Anchor print and ticket print both stay 5x7 (not 8x10). Reason: 8x10 adds envelope weight and cost; Patrick chose to hold shipping cost over print size. Consequence: neither print holds a wall alone - the sell is the full 12-month grid hung together, not any single month.
- DECIDED - Print carving stays one color. Reason: more colors/layers extends Patrick's timeline per month; one light source per scene is the creative constraint that keeps one color workable.
- DECIDED - Ticket/order-sheet print (the small piece) always pairs with the anchor print: same room or same month, one object from that scene, used/worn rather than pristine (a dirty pan, a ring under a glass) for better shapes at small size. On object-anchor months, the ticket print switches to something flat and graphic (a sign, a matchbook, a stub) so the two pieces aren't the same idea twice.
- DECIDED - December's ticket print is a place setting (fork, knife, spoon) for the restaurant-love anchor print, with no welcome text added. Reason: the place setting already reads as welcome; welcome text only works for month-one subscribers, and every later cohort gets that month's ticket instead, so it doesn't belong on a recurring collectible. The welcome message lives in Patrick's letter instead.

Label printer

- PROPOSED (Marty, pending Brian) - Buy a DYMO LabelWriter 550 (about $130) for address labels, printing directly from an Excel sheet. Reason: cheapest Prime-available option that imports Excel without a mail-merge step. Caveat logged: it's chip-locked to DYMO's own label rolls, no cheap third-party stock; Rollo (about $150) is the alternative if that matters, but it needs a Word mail-merge workflow instead of a direct Excel import.
